Como as extension methods extraíram operações reutilizáveis de vínculo e remoção, enquanto serviços especializados passaram a coordenar consultas, validações e regras do fluxo.

01 · O problema

Por que desafogar a classe de domínio?

Uma entidade como Tarefa já representa dados e comportamentos importantes. Quando toda operação auxiliar também fica dentro dela, a classe cresce e passa a misturar regras centrais com detalhes repetitivos de manutenção de propriedades.

Antes

Detalhes espalhados

Remover um relacionamento exigia lembrar de limpar a navegação, o identificador e o código em cada ponto do sistema.

Risco

Estado parcialmente atualizado

Se apenas DepartamentoId fosse limpo, por exemplo, a entidade poderia continuar carregando dados incoerentes.

Objetivo

Uma intenção por chamada

Em vez de repetir atribuições, o código passa a dizer diretamente: remover departamento, vincular cargo ou vincular usuário.

02 · A mudança

Do detalhe mecânico para a linguagem do domínio

A alteração reduz o ruído dentro de Tarefa. O comportamento continua atuando sobre a mesma instância, mas agora a operação repetitiva possui nome e lugar próprios.

Código anterior

A entidade conhece cada atribuição necessária

Quem lê precisa interpretar seis mudanças para descobrir duas intenções.

// Dentro de Tarefa.AprovarObtencao(...)
DepartamentoId = null;
DepartamentoCodigo = null;
Departamento = null;

CargoId = null;
CargoCodigo = null;
Cargo = null;
Código atual

A entidade expressa o que deseja fazer

Os detalhes ficam centralizados em operações reutilizáveis.

// Dentro de Tarefa.AprovarObtencao(...)
this.RemoverDepartamento();
this.RemoverCargo();
03 · O mecanismo

O que uma extension method faz?

Ela é um método estático que pode ser chamado com a sintaxe de um método da própria instância. Isso melhora a leitura sem alterar a classe original nem usar herança.

TarefaRemocaoExtensions.cs Domain/Extensions 
public static class TarefaRemocaoExtensions
{
    public static void RemoverDepartamento(
        this Tarefa tarefa)
    {
        tarefa.Departamento = null;
        tarefa.DepartamentoId = null;
        tarefa.DepartamentoCodigo = null;
    }
}
  1. A classe é estática. Ela agrupa operações e não precisa ser instanciada.
  2. O método também é estático. Por baixo dos panos, a chamada continua sendo estática.
  3. O primeiro parâmetro usa this. Isso informa ao C# que o método estende Tarefa.
  4. A chamada fica natural. Com using Domain.Extensions, escrevemos tarefa.RemoverDepartamento().
04 · Os helpers

Remover e vincular são duas famílias de operação

A separação por intenção facilita encontrar o comportamento. Uma classe concentra limpeza de vínculos; a outra mantém juntas as propriedades necessárias para criar o relacionamento.

public static void VincularDepartamento(
    this Tarefa tarefa,
    Departamento departamento)
{
    tarefa.Departamento = departamento;
    tarefa.DepartamentoId = departamento.Id;
    tarefa.DepartamentoCodigo = departamento.Codigo;

public static void VincularCargo(
    this Tarefa tarefa,
    Cargo cargo)
{
    tarefa.Cargo = cargo;
    tarefa.CargoId = cargo.Id;
    tarefa.CargoCodigo = cargo.Codigo;
}

public static void VincularUsuario(
    this Tarefa tarefa,
    int usuarioId,
    string usuarioCodigo,

{
    tarefa.Usuario = usuario;
    tarefa.UsuarioId = usuarioId;
    tarefa.UsuarioCodigo = usuarioCodigo;
}
05 · O encadeamento

Onde cada chamada entra no fluxo?

O caminho começa no caso de uso, passa pela preparação, chega ao orquestrador e termina nos serviços especializados. As extensions ficam na última etapa, onde o estado da entidade é realmente atualizado.

Passo 01

CriarTarefa

Inicia o caso de uso e solicita uma tarefa pronta para persistência.

Passo 02

TarefaPreparacaoService

Valida o DTO, realiza o mapeamento e encaminha a entidade para o relacionamento.

Passo 03

TarefaRelacionamentoService

Orquestra usuário, departamento, cargo e a validação de governança.

Passo 04

Serviços especializados

Consultam dados e chamam Remover... ou Vincular....

Leitura precisa

No código atual, TarefaRelacionamentoService não chama as extension methods diretamente. Ele delega para TarefaUsuarioRelacionamentoService e TarefaDepartamentoCargoRelacionamentoService. São esses colaboradores que aplicam as operações sobre Tarefa.

06 · A orquestração

O serviço principal coordena, não executa tudo

O orquestrador define a ordem do fluxo, interrompe em caso de falha e só então aplica a política de governança. Isso deixa explícito o processo sem concentrar consultas e mutações na mesma classe.

TarefaRelacionamentoService.cs Application/Services/EntitiesServices/Tarefas 
public async Task<Resultado> RelacionarAsync(
    Tarefa tarefa,
    TarefaDTO tarefaDTO)
{
    var usuarioResultado =
        await _usuarioRelacionamentoService
            .RelacionarAsync(tarefa, tarefaDTO);

    if (usuarioResultado.TeveFalha)
        return Resultado.Falha(usuarioResultado.Messages);

    var estruturaResultado =
        await _tarefaDepartamentoCargoRelacionamentoService
            .RelacionarAsync(tarefa, tarefaDTO);

    if (estruturaResultado.TeveFalha)
        return Resultado.Falha(estruturaResultado.Messages);

    var governancaResultado = TarefaGovernancaPolicy
        .Validar(usuarioResultado.Dados, estruturaResultado.Dados);

    return governancaResultado.TeveFalha
        ? Resultado.Falha(governancaResultado.Messages)
        : Resultado.Sucesso();
}
Usuário ausente

O colaborador remove o relacionamento

if (tarefaDTO.UsuarioCodigo.IsNullOrEmpty())
{
    tarefa.RemoverUsuario();

Usuário encontrado

08 · Termos técnicos

“Puro” e “encadeado” precisam de contexto

A ideia adotada é válida, mas usar os termos com precisão evita que um júnior aprenda dois conceitos diferentes como se fossem iguais.

Método “puro” no sentido prático

Local, previsível e sem infraestrutura

As extensions não acessam banco, rede, relógio ou serviço externo. Recebem um objeto e argumentos, e atuam apenas sobre esse estado. Nesse sentido prático, são helpers determinísticos de domínio.

Função pura no sentido estrito

Não altera estado externo

Tecnicamente, essas extensions não são funções puras, porque modificam a instância de Tarefa recebida. O nome mais exato é operação de mutação local ou helper de relacionamento.

Sequência atual

Chamadas extension em sequência

RemoverDepartamento() e RemoverCargo() retornam void. Por isso, são chamadas sequenciais, embora componham um fluxo encadeado.

Fluent chaining

Uma forma diferente de API

Um encadeamento fluente retornaria a própria tarefa e permitiria algo como tarefa.RemoverDepartamento().RemoverCargo(). Isso não é necessário para obter o benefício atual.

09 · Resultado

O que essa abordagem melhora?

O ganho aparece na leitura, na reutilização e principalmente na consistência das alterações feitas em relacionamentos representados por várias propriedades.

Ganhos
  • Intenção visível: o nome do método explica a operação.
  • Menos repetição: uma única implementação atende diferentes fluxos.
  • Consistência: navegação, Id e código mudam em conjunto.
  • Entidade mais legível: comportamentos centrais deixam de competir com detalhes mecânicos.
Cuidados
  • Não esconder I/O: extension methods de domínio devem evitar banco e serviços externos.
  • Preservar invariantes: operações críticas precisam continuar fáceis de descobrir e proteger.
  • Evitar uma pasta genérica demais: agrupar por entidade e intenção mantém a navegação simples.
  • Testar o efeito completo: validar todas as propriedades modificadas em cada vínculo.
Nota de revisão do recorte atual

Existe um nome que ainda precisa ser alinhado

TarefaDepartamentoCargoRelacionamentoService chama tarefa.RemoverDepartamentoECargo(), mas TarefaRemocaoExtensions expõe apenas RemoverDepartamento() e RemoverCargo() separadamente. Antes de fechar a implementação, a chamada deve usar os dois métodos existentes ou a operação combinada deve ser criada explicitamente.

Em uma frase

A refatoração separa intenção, coordenação e detalhe.

As extension methods cuidam de pequenas mutações reutilizáveis; os serviços especializados consultam e validam dados; o orquestrador encadeia o processo e propaga falhas. O resultado é uma entidade Tarefa menos inflada e um fluxo mais fácil de ler.
